# Web Framework Notes

Notes for the **Let's Build a Web Framework** section of the TypeScript course.

The project starts with a simple `User` model and will gradually add responsibilities before refactoring them into smaller reusable framework components.


### Project Setup
*2026-09-30*

Created the `web-framework` project and configured Parcel for TypeScript development.

Initialized the project and installed Parcel locally rather than globally:

```bash
npm init -y
npm install --save-dev parcel
```

The development server is started with:

```bash
npx parcel index.html
```

Generated dependencies and Parcel output are ignored:

```gitignore
node_modules/
.parcel-cache/
dist/
```

The current Parcel setup initially treated the project as a library because of fields generated by `npm init`. Removing the unnecessary package fields allowed it to run normally as a browser development server.

A simple `console.log()` in `src/index.ts` confirmed that Parcel was compiling and serving the TypeScript entry file correctly.


### Initial User Model
*2026-10-10*

Created the first `User` model with typed property access and partial updates.


#### Optional `UserProps`

```ts
interface UserProps
{
    name?: string;
    age?: number;
}
```

The `?` makes each property optional, allowing partial updates such as:

```ts
user.set({ age: 9999 });
```

Only the supplied property needs to change.


#### `keyof` Compatibility Difference

The instructor uses:

```ts
get(propName: string): number | string
```

The current TypeScript setup rejects this because `string` could refer to any property name, including one that does not exist on `UserProps`.

The current version uses:

```ts
get(propName: keyof UserProps): number | string | undefined
```

`keyof UserProps` limits the argument to valid keys such as `"name"` and `"age"`.

Because those properties are optional, `undefined` must also be included in the return type.

This is a difference from the instructor's older TypeScript/compiler setup rather than a change to the intended design.


#### Partial Updates with `set()`

```ts
set(update: UserProps): void
{
    Object.assign(this.data, update);
}
```

Reusing `UserProps` avoids repeating the property definitions and supports partial updates.

`update` is simply the parameter containing the changes to apply. `Object.assign()` copies those supplied properties onto the existing user data while leaving properties that were not included unchanged.


#### Parcel Module Difference

Once `index.ts` began importing `User`, the current Parcel setup required the entry script to be explicitly marked as a module.

The instructor uses:

```html
<script src="./src/index.ts"></script>
```

This project uses:

```html
<script type="module" src="./src/index.ts"></script>
```

The instructor's older Parcel setup does not require this attribute. The current setup requires it once `index.ts` begins using ES module syntax such as `import` and `export`.

At this stage, the first working `User` model is in place and ready for the additional responsibilities and refactoring introduced later in the course.
